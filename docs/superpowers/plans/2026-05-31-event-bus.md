# adapto_events Message Bus Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `adapto_events`, an in-process typed pub/sub message bus with hybrid per-subscription delivery (durable log+cursor / ephemeral broadcast), throttle primitives, dead-letter, and adapto_app integration.

**Architecture:** Live delivery via `tokio::broadcast`. Durability via an append-only `_events` store collection + per-subscription cursor (`_event_cursors`); durable dispatchers drain the log from their cursor, so restart catch-up is the same code path as live. Poison events skip-after-N into `_event_deadletter`. The bus routes; heavy work is handed to `adapto_scheduler` by the handler (no crate dependency).

**Tech Stack:** Rust, tokio, serde, serde_json, chrono, thiserror, adapto_store. Mirrors `adapto_scheduler` patterns.

**Spec:** `docs/superpowers/specs/2026-05-31-event-bus-design.md`

## Task 7: Durable dispatcher + cursor + dead-letter + GC

**Files:**
- Modify: `crates/adapto_events/src/dispatch.rs` (add durable loop)
- Modify: `crates/adapto_events/src/bus.rs` (`spawn` starts durable dispatchers + GC task; `shutdown` drains)

- `spawn_durable(subscriber, store, broadcast::Receiver, retry cfg, now_fn)`:
  - Load cursor (or seed last_seq=0).
  - Loop: wait for wake (broadcast recv OR poll fallback every ~200ms OR shutdown).
  - On wake: `drain()` = `load_events_after(store, topic, last_seq)`; for each row
    in order: predicate fail → advance; throttle suppress → advance; else handler
    with retry (exponential backoff, `max_attempts`); success → advance + processed++;
    exhaust → `write_deadletter` + advance + failed++. Persist cursor after each advance.
  - Rate-limit (durable): no token → sleep `wait`, then proceed (work paced, not dropped).
- GC task: every `gc_interval`, for each durable topic compute `min_cursor_seq`
  across that topic's durable subs and `gc_events`; prune dead-letter older than `retention`.
- `shutdown`: signal stop; let in-flight drain within a grace window (mirror scheduler).

- [ ] **Step 1: Write failing tests (tokio, in-memory store):**
  - `durable_handler_processes_and_advances`: durable sub; publish 1 matching event;
    poll until handler flag set (or `sleep`); cursor `last_seq == 1`, processed == 1.
  - `durable_restart_replays_missed`: bus A: publish 2 events (no time for delivery,
    or ephemeral-mode trick) — better: publish 2 events with a handler that counts;
